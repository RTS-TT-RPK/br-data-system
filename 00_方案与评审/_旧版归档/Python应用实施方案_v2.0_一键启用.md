## 0. 一页摘要

### 0.1 要做成什么

一个**完全脱离 Excel 的纯 Python 数据应用**，交付形态是"一个文件夹 + 一个桌面图标"：

- 用户双击桌面上的 **「BR数据系统」** 图标 → 启动器窗口出现 → 点「启动系统」→ 自动打开浏览器界面（或启动器自动完成）。
- **不需要装 Python、不需要装 Excel/Office、不需要命令行、不需要联网**。
- 数据存在本机一个 SQLite 文件里；**一键备份 / 一键恢复 / 一键升级**；可选"局域网模式"，让车间其他电脑用浏览器访问同一套数据（客户端同样零安装）。
- 现有 Excel 的 12 个入口、9 张表、55 条业务规则全部用 Python 重写；Excel 只作为导出文件的格式（由 openpyxl 生成，不依赖 Office 安装），不再参与任何业务运行。

### 0.2 三句话结论

1. **技术路线**：Python 3.13 + Django 5.2 LTS + SQLite(WAL) + HTMX，打包成"便携目录 + 启动器"；用 waitress 在后台跑本地服务，浏览器做界面。
2. **一键的边界**：双击启动/打开、首次运行向导、一键备份/恢复/升级、开机自启、局域网开关——全部在启动器里用按钮完成，用户永远不碰命令行。
3. **规模**：核心开发 **34–48 人日**（含 20% 缓冲约 41–58），日历约 **8–11 周**（每周投入 3–4 天）；利润/排程/工艺分析为二期，另计 15–25 人日。

### 0.3 开工前只需要确认 3 件事

| # | 问题 | 默认假设（本方案按此执行） |
|---|---|---|
| Q1 | 这套系统只在一台电脑上用，还是车间多台电脑都要用？ | 默认**单机**；启动器里一键切"局域网模式"即可多终端（浏览器访问，无需安装） |
| Q2 | 4 张基础数据表（物料性质 4 条、共沸 3 条、储位 4 条、罐型液位表 12×10）要不要沿用？ | **沿用并一次性导入**（这是知识资产，不是测试数据）；业务流水数据全部作废、不迁移 |
| Q3 | 交付形态要"免安装便携文件夹"还是"带安装向导的安装包"？ | 默认**便携文件夹 + 桌面快捷方式**（最省事、最抗变化）；需要的话再加安装包 |

其余问题（界面风格、打印、权限等）都有默认值，见 §11。

## 1. 目标与验收标准

### 1.1 "彻底转向 Python"的定义（验收时逐条核对）

| # | 要求 | 怎么验证 |
|---|---|---|
| 1 | 运行时**不依赖 Excel/WPS/Office** | 在一台没装 Office 的干净 Windows 上跑通全部功能 |
| 2 | 运行时**不依赖 VBA/宏/COM/ODBC** | 代码里无 win32com、无 xlsm 读写、无宏 |
| 3 | 所有业务逻辑在 Python 里 | 库存计算、液位查表、共沸预警、日志、查询、导出全部有 Python 测试 |
| 4 | 数据存在关系数据库 | 单个 `.db` 文件；可用 DB 工具查看；备份=复制/导出 |
| 5 | 原 Excel 不再被打开或保存 | 旧 xlsm 归档只读，系统运行期间不访问它 |
| 6 | 不依赖 C:/Scripts 的 3 个 COS 脚本 | 新系统无 COS 调用；旧脚本归档 |
| 7 | Excel 只作为"导出格式" | 导出 .xlsx 用 openpyxl，无需安装 Excel |
| 8 | 界面是浏览器应用 | 本机浏览器打开；可选局域网内其他电脑访问 |
| 9 | 中文、离线、单人可维护 | 断外网可用；README + 一键脚本；故障有提示 |

### 1.2 "一键启用"的定义（验收时逐条核对）

| # | 场景 | 期望结果 |
|---|---|---|
| 1 | **冷机首次**：干净电脑，双击桌面图标 | 首次向导 ≤3 步（选数据位置 → 设管理员密码 → 可选导入基础数据）→ 自动建库、建账号、生成配置 → 浏览器打开登录页；全程 ≤2 分钟 |
| 2 | **日常启动**：双击图标 | 若服务未启动则启动并打开浏览器；若已在运行则直接打开浏览器；≤10 秒 |
| 3 | **关闭**：点启动器"退出系统" | 停止服务、把数据库完整落盘、写日志 |
| 4 | **一键备份**：点"备份现在" | 生成带时间戳的 zip（数据库+配置+日志），提示路径；每日首次启动自动备份一次 |
| 5 | **一键恢复**：选备份文件 | 二次确认 → 自动停服 → 替换数据库 → 重启 → 提示成功；失败自动回滚 |
| 6 | **一键升级**：用新版本文件夹覆盖程序目录 | 下次启动自动检测版本 → 先备份 → 自动迁移数据库 → 健康检查；失败自动回滚到升级前 |
| 7 | **开机自启**（可选） | 勾选后登录 Windows 自动启动；不勾选则手动 |
| 8 | **局域网模式**（可选） | 勾选后重启，启动器显示本机地址；另一台电脑浏览器输入即可用；不需要装任何东西 |
| 9 | **断外网** | 全部功能可用；备份到网盘失败只提示、不影响业务 |
| 10 | **换电脑/迁移** | 把整个文件夹复制到新电脑，双击即用（数据在文件夹内） |

### 1.3 明确不做

1. 不迁移旧系统的任何业务流水（库存 8 行、投料 2 条、工艺卡/生产记录测试数据）——按用户确认作废。
2. 不做利润/退税/采购/排程/工艺分析（现有文件里没有代码和数据，二期另议）。
3. 不做手机 App、多因素认证、公网部署、付费价格 API。
4. 不做"Excel 前端 + Python 后端"的混合形态（与"彻底去 Excel"目标冲突）。

## 2. 交付形态与总体架构

### 2.1 交付物长什么样

推荐**便携文件夹**（不写注册表、不需要管理员权限，复制即迁移）：

```
BR系统                         ← 整个文件夹可拷到 D:\ 或 U 盘
├─ BR数据系统.exe               ← 双击这个（启动器，GUI，无控制台窗口）
├─ app                         ← Python 代码 + Django 模板/静态文件
├─ runtime                     ← 内置 Python 3.13 运行时（用户不用装 Python）
│   ├─ pythonw.exe
│   └─ Lib\site-packages\       ← Django/waitress/openpyxl 等依赖（离线打包）
├─ data                        ← 数据库 + 配置（最重要的目录）
│   ├─ br.db                    ← SQLite 数据库
│   ├─ config.json              ← 端口、数据目录、局域网开关等
│   └─ secret.key               ← Django 密钥（自动生成）
├─ backup                      ← 一键备份的 zip
├─ logs                        ← 运行日志（按天轮转）
├─ docs                        ← 操作手册（md+txt）、故障排查
└─ 启动开发模式.bat             ← 仅开发/排障用（正常用户不用）
```

- 桌面快捷方式指向 `BR数据系统.exe`，图标自定义，名字"BR数据系统"。
- 可选安装包（Inno Setup）：开始菜单/桌面快捷方式 + 卸载；数据仍放在可配置目录（默认 `%LOCALAPPDATA%\BRSystem`，避免 Program Files 写权限问题）。**默认不做安装包**，便携版最省事。

### 2.2 运行时架构

```
双击 BR数据系统.exe
        │
        ▼
┌──────────────────────────────┐
│ 启动器（tkinter GUI，无控制台）│  ← 单实例检测、首次向导、备份/恢复/升级
│  [启动系统] [打开界面] [备份]  │
│  [恢复] [设置] [日志] [退出]   │
└──────────────┬───────────────┘
               │ 启动/停止
               ▼
┌──────────────────────────────┐
│ waitress（单进程 Web 服务）    │  ← 127.0.0.1:8765（单机）
│  Django 应用（业务+权限+审计） │     0.0.0.0:8765（局域网模式）
│  SQLite(WAL)  data/br.db      │
└──────────────┬───────────────┘
               │ HTTP
               ▼
        默认浏览器（Edge/Chrome）打开 http://127.0.0.1:8765
```

- **为什么用浏览器做界面**：不用为 Windows 桌面 UI 写第二套代码；手机/平板/其他电脑都能用；界面改版只改模板。用户感知仍是"双击一个应用"。
- **为什么用 waitress**：纯 Python、Windows 上稳定、不需要 Nginx/Apache；单进程写 SQLite 最安全。
- **为什么数据放在文件夹里**：备份、迁移、排障都只需操作一个目录；不依赖 OneDrive（OneDrive 同步中的 SQLite 有损坏风险）。
- **单机 → 多终端**：设置里勾选"允许局域网访问"，启动器绑定 0.0.0.0 并提示本机 IP；其他电脑浏览器输入 `http://IP:8765` 即可。数据仍只有一份，不存在同步问题。

### 2.3 技术栈（固定版本）

| 层 | 选型 | 说明 |
|---|---|---|
| Python | 3.13（64 位，内置运行时） | Django 5.2 LTS 官方支持；不用 3.14 |
| Web 框架 | Django 5.2 LTS | 自带账号/权限/ORM/迁移/表单校验/CSRF/后台管理 |
| 数据库 | SQLite 3（WAL） | 单文件、零运维；单进程写；金额存整数分；时间存 UTC |
| 前端 | Django 模板 + HTMX + Alpine.js + Bootstrap 5 | 全部本地静态文件，不引 CDN；离线可用 |
| 服务 | waitress | 单进程、跨平台、Windows 稳定 |
| 启动器 | tkinter（Python 标准库） | 无额外依赖、无控制台、打包简单 |
| Excel 导出 | openpyxl | 只写 .xlsx 文件，不依赖 Office |
| 打包 | 便携目录（推荐）/ PyInstaller onedir + Inno Setup（可选） | 见 §3.9 |
| 测试 | pytest + pytest-django | 规则测试、黄金用例、一键流程测试 |
| 日志 | 标准 logging + RotatingFileHandler | logs/app.log，按天轮转 |

## 3. 一键启用详细设计（本方案的核心）

### 3.1 启动器长什么样

一个约 480×360 的窗口，无控制台，标题"BR数据系统"：

```
┌────────────────────────────────────┐
│  BR 数据系统                        │
│  状态：● 运行中（127.0.0.1:8765）   │
│                                    │
│   ┌────────────────────────────┐   │
│   │      启动系统 / 打开界面     │   │  ← 主按钮（最大）
│   └────────────────────────────┘   │
│   [备份现在]  [恢复…]  [设置…]      │
│   [查看日志]  [开机自启 ☐]  [退出]  │
│                                    │
│  数据目录：D:\BR系统\data          │
│  最近备份：2026-10-27 18:00（成功） │
└────────────────────────────────────┘
```

- **主按钮逻辑**：服务未启动 → 启动服务 → 健康检查通过 → 打开浏览器；服务已启动 → 直接打开浏览器。
- 状态灯：灰=已停止、黄=启动中、绿=运行中、红=异常（附"查看日志"）。
- 窗口关闭按钮 = 最小化到任务栏（不退出）；"退出系统"才停服务。
- 所有操作都有明确的中文提示，不出现 Python 报错堆栈（异常写日志 + 弹窗"操作失败，详情见日志"）。

### 3.2 首次启动流程（冷机，≤2 分钟）

启动器检测到 `data/br.db` 不存在 → 进入"首次向导"（3 步）：

1. **选择数据目录**：默认 `程序目录\data`，可点"浏览"改到 D 盘；显示可用空间；提示"以后备份/迁移就是整个 data 目录"。
2. **设置管理员账号**：用户名（默认 admin）+ 密码（≥8 位，二次确认）；提示"忘记密码可用启动器的《重置密码》功能"。
3. **可选导入基础数据**：勾选"导入内置的物料/共沸/储位/液位表"（默认勾选）；不勾选则从空库开始，可在系统里补录或导入 Excel 模板。

点"完成"后自动执行：

```
创建目录 → 生成 secret.key → 建数据库（Django migrate）
→ 写入系统参数 → 导入 4 张基础表（如果勾选）
→ 建管理员账号 → 生成首次备份 backup/初始备份_时间戳.zip
→ 启动服务 → 打开浏览器登录页 → 提示"请用刚设置的账号登录"
```

失败处理：任一步失败 → 弹窗说明失败步骤 + 日志路径；已创建的文件保留在 `data\_init_failed\` 便于排查，用户可重试或联系维护人。

### 3.3 日常启动流程

```
双击 → 单实例锁检测
  ├─ 已有实例在运行 → 直接把浏览器打开到系统地址（不重复启动）
  └─ 未运行 → 读取 data/config.json（端口、是否局域网）
        → 启动 waitress（后台线程/子进程）
        → 轮询 /healthz（最多 15 秒）
        → 成功：打开浏览器；失败：弹窗 + 日志
```

- 端口默认 **8765**；被占用时自动尝试 8766–8775，并写回配置；启动器显示实际端口。
- 服务进程与启动器分离（启动器退出时询问是否停止服务；默认"退出即停止"）。
- 启动时自动检查：数据库可写、磁盘剩余 > 1GB、昨天备份是否存在；异常在状态栏红字提示。

### 3.4 一键备份 / 恢复

**备份**（按钮或每日首次启动自动执行）：

1. 调用 SQLite 在线备份 API（`Connection.backup()`）生成一致性副本 `data/_backup_tmp.db`。
2. 打包 `_backup_tmp.db + config.json + secret.key + 最近 7 天日志` 为 `backup/BR备份_YYYYMMDD_HHMMSS.zip`。
3. 计算 SHA256 写进 zip 内的 `manifest.json`。
4. 保留策略：最近 30 个 + 每月 1 个（自动清理旧文件）；可选"复制到 OneDrive/移动硬盘"目录。
5. 弹窗显示备份路径、大小、耗时。

**恢复**：

1. 选择 zip → 校验 manifest/SHA256 → 显示"将覆盖当前数据（当前库会先自动备份），确认？"。
2. 停服务 → 把当前 `data` 重命名为 `data_before_restore_时间戳` → 解压备份到 `data` → 启动 → 健康检查。
3. 失败则自动切回原目录并提示。

### 3.5 一键升级

升级包 = 新版本的程序目录（不含 data）。用户把新文件夹解压覆盖旧程序目录（data 不在里面，不会被动到）：

```
启动器启动时比对 app/version.txt 与 data/last_version.txt
  ├─ 版本相同 → 正常启动
  └─ 版本更高 → 依次执行：
       1) 自动备份（同 §3.4）
       2) 记录当前版本到 data/upgrade.log
       3) 运行 Django migrate（数据库结构升级，只增不删）
       4) 启动 + /healthz + 冒烟检查（查询、登录）
       5) 成功：更新 last_version，提示"已升级到 x.y.z"
       6) 失败：停服 → 恢复升级前备份 → 回退 app 目录（保留 upgrade_failed 副本）→ 提示
```

约束：**升级只动程序，不动 data**；迁移脚本只做兼容性变更；每次升级前强制备份。用户不需要执行任何命令。

### 3.6 开机自启（可选）

- 勾选"开机自启"：在 `shell:startup` 放一个指向启动器的快捷方式，带参数 `--minimized`（只启动服务，不弹窗口；需要时双击图标打开界面）。
- 取消勾选：删除该快捷方式。
- 不写注册表 Run 键，避免杀毒软件敏感。

### 3.7 局域网模式（可选，满足多终端）

- 设置窗口里勾选"允许局域网访问"→ 保存 → 重启服务。
- 启动器自动：
  1. 绑定 `0.0.0.0:8765`；
  2. 显示本机 IPv4 地址和使用说明（`http://192.168.x.x:8765`）；
  3. 首次开启时提示"需要在 Windows 防火墙放行 8765 端口"，提供"一键放行"按钮（调用 `netsh advfirewall`，需管理员确认一次）。
- 其他电脑：浏览器输入地址 → 登录页 → 各自账号登录；**不需要安装任何软件**。
- 安全默认：单机模式只绑 127.0.0.1；局域网模式强制每个用户独立账号；首次登录强制改初始密码。

### 3.8 目录与配置

| 路径 | 内容 | 是否随备份 |
|---|---|---|
| `data/br.db` | 全部业务数据 | 是 |
| `data/config.json` | 端口、数据目录、局域网开关、备份策略 | 是 |
| `data/secret.key` | Django 密钥（会话/CSRF） | 是（恢复后会话失效需重登） |
| `data/last_version.txt` | 已运行版本 | 是 |
| `backup/` | 备份 zip | 否（单独备份） |
| `logs/` | 运行日志 | 最近 7 天进备份 |
| `app/` `runtime/` | 程序与运行时 | 否 |

- 安装/迁移：复制整个文件夹 → 双击 → 数据跟着走。
- 禁止把 `data/` 放进 OneDrive/网盘同步目录（SQLite 在同步中可能损坏）；备份 zip 可以放网盘。

### 3.9 打包方案（两种，推荐 A）

**方案 A（推荐）：便携目录 + 内置 Python 运行时**
1. 下载官方 Python 3.13 embeddable 包，解压到 `runtime/`；启用 `site-packages`。
2. 用开发机 `pip download` 把全部依赖 wheel 下到 `wheelhouse/`，在目标运行时里离线安装（或直接把开发机 venv 的 site-packages 复制进去）。
3. 代码放 `app/`；启动器用 `pythonw.exe` 运行（无控制台）。
4. 用 `build_portable.ps1` 一键生成上述目录（清理 pyc、写版本号、校验依赖）。
5. 桌面快捷方式：指向 `runtime/pythonw.exe app/launcher.pyw`，图标 `app/static/icon.ico`；或做一个小 `BR数据系统.exe`（仅启动器外壳，用 PyInstaller 单文件即可，体积小）。

**方案 B（可选）：PyInstaller + Inno Setup**
- 适合"想要开始菜单/卸载程序"的场景；把 Django 模板/静态/迁移文件打进 onedir 包，启动器同样用 tkinter。
- 代价：构建脚本要维护 hidden imports、体积 150–250MB、少数杀毒软件可能误报；升级时替换整个安装目录。
- **建议先用 A 跑通全流程，B 作为后期包装，不影响功能。**

### 3.10 异常与自恢复（"傻瓜化"清单）

### 5.2 必须保真的业务规则（55 条见 v1.0 §5，这里列最容易踩的 12 条）

1. 仓库"数量"=体积（m³）；储罐"数量/液位"=液位（m），体积靠罐型+液位查表。
2. 重量（t）= 体积（m³）× 密度（g/mL）；总价（元）= 体积 × 密度 × 市场参考价（元/吨）。
3. 价格是"下限-上限"文本时，默认按**下限**计算；界面要显示"按区间下限"。
4. 储罐液位默认必须命中标定表（0.01 m 网格）；可选线性插值（默认关）；越界/缺口拒绝并提示。
5. 共沸预警只在性质=原料/再加工时触发；用成分明细逐个匹配；"无稳定共沸"的 4 组不预警。
6. 成分明细按"、"切分，取百分号/第一个数字之前的文字；**不能用"第一个数字之前"**（会把"2-甲基四氢呋喃"变成空名）。
7. 库存名称查不到物料/密度/价格时，**阻断保存**并提示补主数据（不再静默算 0）。
8. 五金是"正入负出"的流水；结存=sum；预警按结存，不按单行。
9. 出库不能超过当前库存；储罐出库到 0 时走"关闭"而非物理删除。
10. 区域容积率 = 区域体积合计 / 区域最大方量合计；分母 0 显示 N/A；可 >100% 并提示"标称口径待确认"。
11. 工艺卡/生产记录必填塔号+名称；修改/删除要留审计。
12. 查询默认最近 30 天；结果可分页、可导出 Excel；删除要二次确认。

### 5.3 权限与审计

- 三档角色：管理员（用户/参数/基础数据/删除）、录入员（业务录入+查询）、只读（查询+导出）。
- 每个写操作同事务写审计：谁、何时、哪个模块、前值/后值、IP、请求号。
- 审计表只允许插入，不允许 UI 修改/删除；数据库层面加权限/触发器保护。
- 登录失败锁定、密码强度、会话超时；局域网模式强制独立账号。

### 12.3 旧系统退役清单（验收通过后执行）

1. 旧 `BR数据库云端版.xlsm` 与 `legacy_BR数据库.xlsm` 移入 `归档/2026-xx-xx/`，设为只读，宏禁用说明。
2. 停用 `C:\Scripts` 的 3 个 COS 脚本：移到归档目录，**删除/轮换其中的明文密钥**。
3. 在腾讯云 COS 控制台轮换密钥或删除旧密钥；如不再需要 COS，可清空/保留只读归档桶。
4. 通知所有使用过旧文件的同事：新系统地址、账号、停止使用旧文件。
5. 保留旧文件只读至少 30 天，作为回退与追溯；之后按公司数据留存规定处理。

### 12.4 给评审 AI 的审查清单（重点攻击这 10 点）

1. **"一键启用"的交付形态**：便携文件夹 + 内置 Python 运行时 + tkinter 启动器，是否比"单文件 exe"更稳？有没有更适合非程序员的方案？
2. **打包方案**：便携运行时 vs PyInstaller onedir vs 安装包，对"一人 + AI 维护、Win10/11、可能被杀毒拦截"的场景，哪个最优？请给出你推荐与备选。
3. **单机默认 + 局域网开关**是否能覆盖用户未来 1–2 年的多终端需求？切换成本估计是否合理？
4. **不迁移历史业务数据**是否合理？只迁 4 张基础表是否足够？有没有被忽略的"知识资产"（如储位命名、罐型、价格口径）？
5. **Django + SQLite + waitress 单进程**，在单机/3–5 终端下是否足够？何时必须升级到 PostgreSQL/服务器部署？
6. **启动器的备份/恢复/升级逻辑**是否有遗漏的失败路径（磁盘满、权限、杀毒、断电）？恢复流程是否够安全？
7. **两套数据目录策略**（便携 data/ vs %LOCALAPPDATA%）哪个更适合非程序员？如何避免用户把 data 放进 OneDrive？
8. **16 张表的模型**是否过度设计/缺约束？无历史数据时是否可以更简化？
9. **工期 34–48 人日**是否低估（打包、干净机调试、UAT、文档）？给出你的区间。
10. **验收标准**是否可执行？还缺哪些"一键"场景（多显示器、中文路径、非管理员账户、老旧 Win10、Office 未装等）？
