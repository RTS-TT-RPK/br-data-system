# 宽表 / 长表 / 成分明细 数据结构说明 v1.0

> 用途：给面板引擎、插件接入、Agent 工具、导入导出共用的数据结构契约。
> 依据：02_图像识别工作区的 ⑩_这一行怎么存进数据库.sql、facts.jsonl、schemas/来料分析_v1.json、插件工作流程_v3.md。
> 状态：草案，随第一个面板跑通后修订。

---

## 1. 三件套

| 层 | 是什么 | 给谁用 | 存哪 |
|---|---|---|---|
| 宽表 | 一行 = 一个业务对象；列 = Excel 表头 | 人看、审核、导出 | record.data_json |
| 读数 | 一行 = 一个普通数值（液位/密度/使用率/数量…） | 机器查 | record_reading |
| 成分 | 一行 = 一个成分/指标（含原文） | 机器查、成分分析 | record_component |

三者由同一次保存/接入生成；宽表保留原文，长表保留可比较的值。

## 2. 宽表记录 record

~~~json
{
  "id": 1001,
  "panel_key": "br_inventory",
  "panel_version": 3,
  "data_json": {
    "储位": "示例库区1#",
    "储存区域": "示例库区",
    "日期编号": "2026-10-01",
    "来源": "产品",
    "名称": "示例溶剂A",
    "性质": "正常",
    "成分明细": "示例溶剂A90% 水5%、PH7",
    "数量/液位": "4.33",
    "体积": "",
    "重量": "",
    "总价": ""
  },
  "source_type": "plugin",
  "source_run_id": "20990101_001",
  "source_row_id": "R001",
  "status": "confirmed",
  "image_id": 55,
  "confidence": 0.93
}
~~~

要点：
- data_json 保留该行所有列的原值（含成分明细原文）；空值就是空，不补算。
- panel_version 记录保存时的面板定义版本；面板改列后旧记录按旧版解释。
- status：draft（草稿）/ confirmed（已确认）/ void（作废）/ deleted（软删除）。
- source_type：manual / agent / plugin / import。
- image_id 指向 attachment（原图/来源图）。

## 3. 读数 record_reading

| 字段 | 类型 | 说明 |
|---|---|---|
| record_id | int | 所属记录 |
| field_key | text | 对应面板列 key |
| name | text | 指标名（液位/密度/使用率…） |
| numeric_value | decimal | 归一后的数值 |
| unit | text | 吨 / % / — / 其他 |
| raw_text | text | 图上原文 |
| category | text | measurement / capacity / price / other |
| confidence | float | 0–1，可空 |

规则：
- 只有“可比较的数”才进读数表；纯文本列留在 data_json。
- 百分比：usage 65% → numeric_value=65，unit="%"，raw_text="65%"（与成分不同：成分存小数，读数按原单位；如要统一可后续调整，见 §7 待定）。
- 密度 0.7880 → numeric_value=0.7880，unit="—"，raw_text="0.7880"。

## 4. 成分 record_component

| 字段 | 类型 | 说明 |
|---|---|---|
| record_id | int | 所属记录 |
| field_key | text | 来源列 key（如 components / 成分明细） |
| component_std | text | 标准名（可空；未匹配时用原文） |
| component_original | text | 图上原文名 |
| numeric_value | decimal | 百分比存小数（90% → 0.9）；非百分比存原值 |
| unit | text | % / — / 其他 |
| raw_text | text | 图上原文段（如 示例溶剂A90%） |
| category | text | comp / water / misc / other |
| confidence | float | 0–1，可空 |
| material_id | int | 可空；关联标准物料 |

### 4.1 归一规则

- 百分比：90% → 0.9；显示时 ×100 并补 %。
- 小数、整数、PH 等：按原值存，unit 用 —。
- 单位不带进 numeric_value；单位单独存。
- 数值末尾 0 不保留（0.7880 → 0.788）；要看原样看 raw_text。

### 4.2 分类规则

| category | 含义 | 参与合计 |
|---|---|---|
| comp | 正常成分 | 是 |
| water | 水/水分/含水 | 否（按图像识别工作区默认） |
| misc | 杂/杂质/其他/残余 | 有值才计 |
| other | 指标（PH、酸度等） | 否（默认） |

面板定义里可覆盖：measurements.categories、sum_max（默认 100%）。

### 4.3 拆分与原文对账（硬规则）

原格：示例溶剂A90% 水5%、PH7

拆成：

~~~json
[
  {"name":"示例溶剂A","raw_value":"90%","raw_segment":"示例溶剂A90%"},
  {"name":"水","raw_value":"5%","raw_segment":"水5%"},
  {"name":"PH","raw_value":"7","raw_segment":"PH7"}
]
~~~

对账：所有 raw_segment 按顺序拼接（忽略空白、顿号、逗号、分号、斜杠）必须等于原格原文。
不通过 → 拒绝入库，生成问题（issue），人工处理；不自动改、不猜。

### 4.4 合计校验

- 按面板 measurements 配置计算：sum = 参与合计的 numeric_value（百分比小数）×100。
- 超过 sum_max（默认 100）报问题；不自动调整。
- 水默认不计；杂有值才计；其他指标默认不计。
- 允许“未纳入合计”的项，但要在面板定义中标注。

## 5. 长表导出 facts

导出列（与图像识别 facts.jsonl 对齐，增加 record/panel 字段）：

~~~text
panel_key, record_id, source_type, source_run_id, source_row_id,
record_date, location, batch_id, container_id, material_name, supplier,
fact_type（component/reading）,
component_standard_name, component_original_name,
name, numeric_value, unit, raw_value, category, confidence
~~~

- 成分：一行一个成分。
- 读数：一行一个指标（fact_type=reading）。
- 未确认（draft）不导出；void/deleted 不导出。

## 6. 插件/Agent 接入 payload

### 6.1 标准 JSON

~~~json
{
  "panel_key": "incoming_analysis",
  "source": {
    "type": "dsh_plugin",
    "run_id": "20990101_001",
    "image_sha256": "…",
    "image_path": "inbox/IMG_001.jpg",
    "extractor": {"name": "dsh-table-extract", "version": "1.2"}
  },
  "document_type": "来料分析",
  "rows": [
    {
      "row_key": "R001",
      "fields": {"日期":"2026-10-27","位置":"示例库区1#","物料":"示例溶剂A","批次":"DEMO-001","桶号":"D01","厂商":"示例供应商"},
      "components": [
        {"name":"示例溶剂A","raw_value":"90%"},
        {"name":"水","raw_value":"5%"},
        {"name":"PH","raw_value":"7"}
      ],
      "readings": [
        {"name":"液位","raw_value":"4.33","unit":"吨"}
      ],
      "uncertain": [],
      "confidence": 0.93
    }
  ]
}
~~~

### 6.2 拆分格式（兼容图像识别工作区）

~~~json
{
  "fields": {"成分明细":"示例溶剂A90% 水5%、PH7"},
  "拆开": {"成分明细":[
    {"名字":"示例溶剂A","值":"90%","原文段":"示例溶剂A90%"},
    {"名字":"水","值":"5%","原文段":"水5%"},
    {"名字":"PH","值":"7","原文段":"PH7"}
  ]}
}
~~~

应用把“拆开”转成 components；原文段保留为 raw_text；对账规则同上。

### 6.3 如果只有 SQL

不执行。适配器只解析：

~~~sql
INSERT INTO <白名单表> VALUES (...);
~~~

- 只允许 INSERT；禁止 UPDATE/DELETE/DDL/多语句/函数调用。
- 表名/列数/类型必须匹配映射表；否则拒绝并报问题。
- 解析出的值转成 §6.1/6.2 JSON，再走同一校验。
- 更推荐让插件直接输出 JSON；SQL 是兼容层，不是主路径。

## 8. 示例：来料分析一行

宽表显示：

| 日期 | 位置 | 物料 | 批次 | 桶号 | 厂商 | 成分明细 |
|---|---|---|---|---|---|---|
| 2026-10-27 | 示例库区1# | 示例溶剂A | DEMO-001 | D01 | 示例供应商 | 示例溶剂A90% 水5% PH7 |

成分表：

| 成分 | 数值 | 单位 | 原文 | 分类 |
|---|---|---|---|---|
| 示例溶剂A | 0.9 | % | 示例溶剂A90% | comp |
| 水 | 0.05 | % | 水5% | water |
| PH | 7 | — | PH7 | other |

查询：哪些物料含水最高？

~~~sql
SELECT r.data_json->>'名称' AS material, c.numeric_value
FROM record_component c JOIN record r ON r.id=c.record_id
WHERE c.category='water' AND r.panel_key='br_inventory'
ORDER BY c.numeric_value DESC LIMIT 10;
~~~

（SQLite JSON1 语法；实际实现用 ORM/查询构造器。）
