## 三、关键架构决策

| 决策 | 原因 | 备注 |
|---|---|---|
| Django + SQLite | Windows 单机、无 WSL/Docker、用户非程序员 | 不现在换 PostgreSQL |
| 面板 JSON 驱动 | 表格多、列经常变 | 特殊业务仍走专用 service |
| data_json + Component 长表 | 原始事实 + 可查询派生 | 原文是权威，成分是派生 |
| search_text | SQLite 存储中文 JSON 会转 \uXXXX，icontains 查不到 | 所有写入统一重建 |
| Agent 只能交草稿 | 防止 AI 直接写正式账 | 人工审核是硬边界 |
| Excel 报表用 openpyxl | 不依赖 Office/WPS 宏 | 照参考样式，不复制公式 |

## 五、踩过的坑（下次别再踩）

1. SQLite 中文 JSON 搜索：data_json__icontains 对中文无效，必须用 search_text；所有写入口都要更新它。
2. Windows 批处理：启动预览.bat 必须 ASCII + CRLF；中文 echo/UTF-8 会报“不是内部命令”。
3. runserver 缓存：--noreload 改模板/视图后不生效，重启即可；正常启动用自动重载。
4. Django 测试：ALLOWED_HOSTS 要加 testserver，否则测试 400。
5. 成分名重复：payload 同时给 name 和 raw_value 时，raw_value 可能已含 name，导致“示例溶剂B示例溶剂B”；写入前统一由原文重解析。
6. 别名不统一：分析用 canonical，查询用原始 component_std 会不一致；已在成分条件查询里做 alias_variants 统一（正庚烷/庚烷等）。
7. 重复原文：示例数据 Record#9001/9002 的成分原文包含两段（示例溶剂A/水重复），不自动合并；一致性命令只提示，不修改。
8. 报表样式：不要复制原工作簿公式/宏；用 openpyxl 生成静态度量值，样式对齐即可。

## 六、Agent 接入约定

- 入口：POST /api/ingestions
- 必填：panel_key、rows（1–500）
- 幂等：Idempotency-Key 头或 payload.idempotency_key；相同内容也会按 payload_hash 去重
- row_key 在批次内唯一
- 可选鉴权：环境变量 BR_API_TOKEN，请求头 X-API-Key
- 响应：batch_id + review_url；重复时 duplicate=true
- 人工审核：/ingestions/<id>/
- 不允许 Agent 直接改正式记录/执行 SQL
- 详细文档：03_原型与代码/实现架构与Agent接入说明.md
